# 1. ad-hoc 介绍
- ansible 执行方式的其中一种是 ad-hoc , 就像一条Linux命令, 一次性只能执行一个模块 
- ansible 执行方式的另外一种是playbook, 就像一个shell脚本文件, 可以一次性调用多个ansible的模块, 而且playbook中还可以实现条件判断、循环等高阶特性
- **ad-hoc 语法格式** 
	- ```bash
		命令 : ansible 主机 -m 模块 -a '模块参数' ansible选项
			ansible all -m shell -a 'useradd zhangsan' -uroot -k
	  ```

# 2. 命令执行模块
- ansible 的命令执行模块, 就是相当于在被控节点直接去执行shell命令, 所以叫做命令执行模块
- 而这些命令执行模块和其他的模块之间有一个很大的区别: 命令执行模块不具备幂等性
	- 幂等性: 执行一次任何或者多次执行任务, 结果只要是一样的, 那么就不会发生任何改变
		- 调用user模块去被控节点创建用户: 第一次调用的时候, 创建了用户, 第二次调用的时候, 已经存在的用户, 结果是一样的, 不会发生任何改变
- **shell 模块** 
	- 本质就是执行shell命令, 支持一些高阶参数: 如creates、removes、chdir
		- creates : 判断文件是否存在, 存在则不执行后面的操作, 不存在则执行后面的操作 
		- removes : 判断文件是否存在, 不存在则不执行后面的操作, 存在则执行后面的操作 
		- chdir : 运行命令前先切换到指定目录
- command 模块 
	- 和shell模块一模一样, 只不过有一些特殊符号不支持"<", ">", "|",
        ";"  "&"
- raw 模块 
	- 和shell模块也是一模一样, 但是不支持shell模块和command模块的那些参数
	- **执行任务的时候是直接SSH远程执行命令, 并没有将模块封装为py脚本去执行, 所以raw模块可以在没有python环境下的被控节点执行任务** 
- script 模块 
	- 在被控节点执行主控节点的shell脚本
	- 实际上并不是将shell脚本推送到远程主机执行, 而是在主控节点上读取脚本的shell命令, 把shell命令推送到被控节点执行
- 例题
	- ```bash
		[root@mubai632 ~]# cat 1.sh
		#!/bin/bash
		ansible all -m shell -a 'rm -rf /etc/yum.repos.d/* && \
		umount /opt/mount && \
		rm -rf /opt/mount && \
		mkdir /opt/mount && \
		mount /dev/sr0 /opt/mount && \
		cat > /etc/yum.repos.d/local.repo << "EOF"
		[base]
		name=base
		baseurl=file:///opt/mount/BaseOS
		gpgcheck=0
		enabled=1
		[app]
		name=app
		baseurl=file:///opt/mount/AppStream
		gpgcheck=0
		enabled=1
		EOF
		  yum install -y httpd && \
		  systemctl restart httpd.service&& \
		  systemctl stop firewalld && \
		  echo web > /var/www/html/index.html
		  '
	  ```

# 3. 常用模块
## 3.1 文件管理模块
- 文件管理模块
	- file 
	- fetch 
	- copy 
- **file : 在被控节点查看文件信息、创建 | 删除 | 修改普通文件/目录文件** 
	- **查看node节点的/etc/passwd文件信息** 
		- ```bash
			命令 : ansible node1 -m file -a 'path=/etc/passwd state=file'
				path=文件  # 必须写
				state=动作  
					file 返回路径的当前状态
					absent 删除文件
					directory 没有目录, 会创建过程中的所有目录
					touch 不存在则创建文件, 也可以修改
					link 创建软链接, 当状态为link的时候, 不需要写path, 需要写src和dest
		  ```
	- **在被控节点上创建/opt/file文件, 要求文件的拥有人是user632, 拥有组是root, 文件权限是777** 
		- ```bash
			命令 : ansible nodes -m file -a 'path=/opt/file state=touch owner=user632 mode=0777'
		  ```
	- **修改node2节点上的/opt/file文件信息, 将文件的拥有人修改为root** 
		- ```bash
			命令 : ansible node2 -m file -a 'path=/opt/file state=file owner=root'
		  ```
	- **在所有的节点上创建/opt/dir目录** 
		- ```bash
			命令 : ansible nodes -m file -a 'path=/opt/dir state=directory'
		  ```
	- **删除所有节点上的/opt/dir目录文件** 
		- ```bash
			命令 : ansible nodes -m file -a 'path=/opt/dir state=absent'
			# file模块只能一个文件一个文件的删除, 不支持批量删除文件
		  ```
	- **在node1节点上创建软链接文件/opt/passwd, 源文件指定/etc/passwd** 
		- ```bash
			命令 : ansible node1 -m file -a 'src=/etc/passwd dest=/opt/passwd state=link'
		  ```
- copy : 实现控制节点和被控节点文件的传输; 把控制节点的文件传输给被控节点, 在被控节点自身上进行文件拷贝, 支持将内容直接写入到文件中 
	- 常用参数
		- backup : 在覆盖文件之前先备份一份, 备份的文件名以时间命名
		- content : 把内容写到文件中
		- dest : 目标文件
		- src : 源文件
		- remote_src : 如果为yes, 则src表示被控节点路径, 如果为false, 则src表示主控节点的路径
		- force : 是否要覆盖文件, true覆盖, false不覆盖, 默认是true
	- **将控制节点的/etc/passwd拷贝到所有的被控节点的/tmp目录下** 
		- ```bash
			命令 : ansible nodes -m copy -a 'src=/etc/passwd dest=/opt/test/ backup=yes'
			# 两次执行这个命令, backup参数不会创建带有时间戳的备份文件, 因为ansible在copy模块中会对比src和dest的文件的校验和, 判断两个文件是否相同, 如果相同则不会发生覆盖以及备份文件
		  ```
	- **将node1节点的/etc/passwd文件拷贝到自己节点的/opt目录下, 修改名/opt/passwd-node1** 
		- ```bash
			命令 : ansible node1 -m copy -a 'remote_src=yes src=/etc/passwd dest=/opt/passwd-node1'
		  ```
	- **使用copy模块将httpd index 内容写入到/var/www/html/index.html文件** 
		- ```bash
			命令 : ansible all -m copy -a 'content="httpd index" dest=/var/www/html/index.html'
		  ```
- fetch : 将被控节点的文件拷贝到控制节点上, **只能拉取普通文件, 目录是无法拷贝过来的, 默认情况下, 拉取过来的文件在控制节点上是以被控节点主机名的名字作为目录名字来存储的** 
	- 将所有的被控节点的/etc/passwd文件保存到控制节点的/opt目录下
		- ```bash
			命令 : ansible all -m fetch -a 'src=/etc/passwd dest=/opt'
			# 拉取下来会以目录结构存储:主机名/etc/passwd
		  ```
	- 直接拉取文件, 不要以目录结构存储
		- ```bash
			命令 : ansible all -m fetch -a 'src=/etc/passwd dest=/opt/ flat=true'
			# 加上flat=true, 目标目录后面一定要加/
		  ```

## 3.2 软件管理模块
- 软件管理模块
	- yum_repository模块 : 管理yum仓库配置文件(创建配置文件往里面写内容, 修改配置文件的内容)不能删除yum仓库配置文件
	- yum模块 : 管理软件包的, 比如安装、更新、卸载...
- **yum_repository 模块** 
	- 常用参数
		- file : 指定 yum 配置文件的, 不需要指定 **`.repo`** 后缀
		- name : 对应配置文件中的[ ] , 仓库名
		- description : 对应配置文件的中 name 内容 
		- baseurl : rpm 位置 
		- gpgcheck : 对应配置文件中的 gpgcheck 
		- gpgkey : 对应配置文件中的 gpgkey 
		- enabled : 对应配置文件中的 enabled 
		- state : present 创建仓库以及修改的含义, absent 删除仓库
	- 在所有的被控节点创建yum配置文件, 要求文件名称为dvd.repo, 文件中包含俩个仓库, 仓库信息如下
		- ```bash
			[base]
			name=base
			baseurl=file:///opt/mount/BaseOS
			gpgcheck=0
			enabled=1
			[app]
			name=app
			baseurl=file:///opt/mount/AppStream
			gpgcheck=0
			enabled=1
			
			命令 : ansible nodes -m yum_repository -a 'file=dvd name=base description=base basurl=file:///opt/mount/BaseOS gpgcheck=0 enabled=1'
			命令 : ansible nodes -m yum_repository -a 'file=dvd name=app description=app baseurl=file:///opt/mount/AppStream gpgcheck=0 enabled=1'
			# 每一条只能创建一个仓库
		  ```
- **yum 模块 : 可以对包和包组进行管理** 
	- 常用参数 
		- name : 指定包霍包组的名字
		- state : absent卸载, latest更新, present安装
	- **安装nginx软件包** 
		- ```bash
			命令 : ansible nodes -m yum -a 'name=nginx state=present'
		  ```
	- **安装Development Tools软件包组** 
		- ```bash
			命令 : ansible nodes -m yum -a 'name="@Development Tools" state=present'
			# 安装包组需要在包组名前加 @ 
		  ```
	- **卸载nginx软件包(不会同时卸载依赖包)** 
		- ```bash
			命令 : ansible nodes -m yum -a 'name=nginx state=absent'
		  ```

## 3.3 服务管理模块
- 服务管理模块
	- service 
	- systemd 
	- systemd模块多了daemon_reload参数, 相当于执行了systemctl daemon-reload, 一旦修改了服务的服务单元配置文件, 一定要daemon-reload才能够读取到. 其他的参数都是一样
	- 常用参数
		- name : 操作哪个服务
		- state : started, stopped, restarted, reloaded
		- enabled : 是否实现开机自启
	- 重启httpd服务, 并实现开机自启
		- ```bash
			命令 : ansible nodes -m systemd -a 'name=httpd state=restarted enabled=1'
		  ```

## 3.4 用户管理模块
- 用户管理模块
	- user模块 : 管理用户的
	- group模块 : 管理用户组的
- **user 模块** 
	- 创建lisi用户, 要求uid是3300, gid是3300, 附加组是root, 描述信息是web user, 登录shell是/bin/bash
		- ```bash
			命令 : ansible nodes -m user -a 'name=lisi uid=3300 groups=root comment="web user" shell="/bin/bash"'
		  ```
	- 修改lisi用户信息, 将其登录shell修改为/sbin/nologin 
		- ```bash
			命令 : ansible nodes -m user -a 'name=lisi shell="/sbin/nologin"'
		  ```
	- 删除lisi用户, 删除用户的要删除家目录和邮箱文件, 所以这里需要额外添加一个参数remove=1
		- ```bash
			命令 : ansible nodes -m user -a 'name=lisi state=absent remove=1'
		  ```
- **group 模块** 
	- 创建用户组itgroup, gid是6666
		- ```bash
			命令 : ansible nodes -m group -a 'name=itgroup gid=6666'
		  ```
	- 修改组的gid为7777 
		- ```bash
			ansible nodes -m group -a 'name=itgroup gid=7777'
		  ```
	- 删除用户组
		- ```bash
			命令 : ansible nodes -m group -a 'name=itgroup state=absent'
		  ```

## 3.5 计划任务模块
- **cron模块 : 相当于crontab周期性计划任务** 
- 常用参数
	- minute : 分钟
	- hour : 小时
	- day : 日
	- month : 月
	- weekday : 周
	- name : 计划任务名字
	- job : 定义执行的任务
	- user : 以什么用户的身份去执行任务
	- state : 创建/删除
	- cron_file : 指定在哪个文件定义计划任务, 要么是/etc/crontab要么是/etc/cron.d, 不指定默认在 /var/spool/cron/ 目录下
- 在node1节点上, 每天上午9点15分, 以及下午的17点15分, 执行echo hello任务
	- ```bash
		命令 : ansible node1 -m cron -a 'name=job minute=15 hour=9,17 job="echo hello"'
	  ```
- 删除这个任务
	- ```bash
		命令 : ansible node1 -m cron -a 'name=job state=absent'
	  ```

## 3.6 文件下载模块
- get_url : 在被控节点下载文件使用的 
- 常用参数
	- url : 指定下载的文件路径
	- dest : 指定下载的位置
- ```bash
	命令 : ansible all -m get_url -a 'url=https://releases.ansible.com/ansible/ansible-2.9.0.tar.gz dest=/opt'
  ```

## 3.7 解压缩模块
- unarchive 模块 : 可以把控制节点的压缩包解压缩到被控节点, 也可以在被控节点自身上找压缩包然后解压缩到自身另外一个目录
- 常用参数
	- src : 压缩文件的源路径 
	- dest : 解压缩后放到哪个目录下 
	- remote_src : 表示找的压缩文件是否来自于被控节点本身, yes 表示从被控节点本身找压缩包, no表示从控制节点找压缩包, 默认是no
- 例题
	- ```bash
			ansible all -m unarchive -a 'src=demo.tgz dest=/opt'
			ansible all -m unarchive -a 'remote_src=yes src=/opt/ansible-2.9.0.tar.gz dest=/opt'
	  ```

## 3.8 解压缩模块
- synchronize模块 : 相当于执行rsync命令
	- 将被控节点的文件拉取到控制节点上
	- 将控制节点的文件推送到被控节点上
	- 底层其实走的是rsync命令, 而rsync走的是SSH协议
- 常用参数
	- mode : pull/push, 是push src表示控制节点的文件路径, 是哦pull src表示被控节点的路径 
	- src : 文件源路径
	- dest : 文件目标路径
- **传输普通文件** 
	- 将控制节点的/etc/passwd文件同步到所有的被控节点的/opt目录下
		- ```bash
			命令 : ansible all -m synchronize -a 'src=/etc/passwd dest=/opt'
		  ```
	- 将所有的被控节点的/opt/passwd拉取到控制节点的/tmp目录下
		- ```bash
			命令 : ansible all -m synchronize -a 'mode=pull src=/opt/passwd dest=/tmp'
		  ```
- **传输目录文件** 
	- **传输的如果是目录, 那么对于src来说, 后面路径带不带/是存在不同的意义的** 
	- 如果带上了/, 表示同步这个**目录下所有的文件** 
	- 如果没带/, 表示同步这一**整个目录** 
	- 将控制节点的/opt/目录同步到被控节点的/opt目录下
		- ```bash
			[root@adsl-172-10-0-153 ansible]# ansible all -m synchronize  -a 'src=/opt dest=/opt'
			 这个没带/, 同时的是一整个opt目录
			[root@adsl-172-10-0-153 ansible]# ansible all -m synchronize  -a 'src=/opt/ dest=/opt'
			  这个带了/, 同步的是/opt目录下的所有文件
		  ```
