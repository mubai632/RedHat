# 1. ad-hoc 介绍
- ansible 执行方式的其中一种是 ad-hoc , 就像一条Linux命令, 一次性只能执行一个模块 
- ansible 执行方式的另外一种是playbook, 就像一个shell脚本文件, 可以一次性调用多个ansible的模块, 而且playbook中还可以实现条件判断、循环等高阶特性
- **ad-hoc 语法格式** 
	- ```bash
		命令 : ansible 主机 -m 模块 -a '模块参数' ansible选项
			ansible all -m shell -a 'useradd zhangsan' -uroot -k
	  ```

# 2. 命令执行模块
- ansible 的命令执行模块, 就是相当于在被控节点直接去执行shell命令, 所以叫做命令执行模块
- 而这些命令执行模块和其他的模块之间有一个很大的区别: 命令执行模块不具备幂等性
	- 幂等性: 执行一次任何或者多次执行任务, 结果只要是一样的, 那么就不会发生任何改变
		- 调用user模块去被控节点创建用户: 第一次调用的时候, 创建了用户, 第二次调用的时候, 已经存在的用户, 结果是一样的, 不会发生任何改变
- **shell 模块** 
	- 本质就是执行shell命令, 支持一些高阶参数: 如creates、removes、chdir
		- creates : 判断文件是否存在, 存在则不执行后面的操作, 不存在则执行后面的操作 
		- removes : 判断文件是否存在, 不存在则不执行后面的操作, 存在则执行后面的操作 
		- chdir : 运行命令前先切换到指定目录
- command 模块 
	- 和shell模块一模一样, 只不过有一些特殊符号不支持"<", ">", "|",
        ";"  "&"
- raw 模块 
	- 和shell模块也是一模一样, 但是不支持shell模块和command模块的那些参数
	- **执行任务的时候是直接SSH远程执行命令, 并没有将模块封装为py脚本去执行, 所以raw模块可以在没有python环境下的被控节点执行任务** 
- script 模块 
	- 在被控节点执行主控节点的shell脚本
	- 实际上并不是将shell脚本推送到远程主机执行, 而是在主控节点上读取脚本的shell命令, 把shell命令推送到被控节点执行
- 例题
	- ```bash
		[root@mubai632 ~]# cat 1.sh
		#!/bin/bash
		ansible all -m shell -a 'rm -rf /etc/yum.repos.d/* && \
		umount /opt/mount && \
		rm -rf /opt/mount && \
		mkdir /opt/mount && \
		mount /dev/sr0 /opt/mount && \
		cat > /etc/yum.repos.d/local.repo << "EOF"
		[base]
		name=base
		baseurl=file:///opt/mount/BaseOS
		gpgcheck=0
		enabled=1
		[app]
		name=app
		baseurl=file:///opt/mount/AppStream
		gpgcheck=0
		enabled=1
		EOF
		  yum install -y httpd && \
		  systemctl restart httpd.service&& \
		  systemctl stop firewalld && \
		  echo web > /var/www/html/index.html
		  '
	  ```

# 3. 常用模块
## 3.1 文件管理模块
- 文件管理模块
	- file 
	- fetch 
	- copy 
- file : 在被控节点查看文件信息、创建 | 删除 | 修改普通文件/目录文件
	- 查看node节点的/etc/passwd文件信息
		- ```bash
			命令 : ansible node1 -m file -a 'path=/etc/passwd state=file'
				path=文件  # 必须写
				state=动作  
					file 返回路径的当前状态
					absent 删除文件
					directory 没有目录, 会创建过程中的所有目录
					touch 不存在则创建文件
		  ```
