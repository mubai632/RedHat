# 1. playbook 介绍
- playbook . 就是剧本
- 所谓的 playbook 就是一个文件, 里面通过 yaml 语法进行编写, 可以在 playbook 中调用多个模块, 同时还支持变量的定义和引用、支持判断语句、支持循环语句...
- 特点: 按照顺序来执行剧本中的任务的(这个任务就是要在被控节点执行的任务, 一个任务调用一个ansible模块), 一旦中间有某个任务失败了, 那么ansible就会停止在这个任务, 后面的任务不会去执行了 
- **如果编写了剧本的话, 那么执行剧本的时候就不能使用ansible命令, 而需要使用 ansible-playbook 命令去执行** 

# 2. playbook 如何编写
- 案例
	- ```bash
		- name: play
		  hosts: all
		  tasks:
		  - name: create lisi user
		    user:
		      name: lisi
		      state: present
		  - name: passwd lisi user
		    shell: echo 1 | passwd --stdin lisi
	  ```

## 2.1 yaml 语法格式
- **yaml语法格式 : 专门为配置文件编写的一种语法格式, 一般都是使用在配置文件上** 
	- **yaml 语法中大小写严格区分** 
	- **yaml 中, 具备层级关系, 使用空格来表示层级关系, 空格的数量多少无所谓, 但是同一个层级下的一定要并齐** 
	- **yaml 中不允许使用tab键来表示层级关闭, 你必须使用空格隔开** 

## 2.2 yaml 数据类型
- 纯量: 是yaml中最小的单位, 是不可以再次分割的单位
- **列表/数组/序列: 一个 `-` 就是代表一个列表, 列表是一组有次序的内容** 
	- 在playbook中, 一个 play 就是一个列表, 一个 task 任务就是一个列表 
- 对象/字典: 表现形式是键值对 **`key: value`** 
	- 在playbook中, 调用的模块、模块的参数这些东西都是对象类型

## 2.3 playbook 的组成和编写
- playbook 是由多个 play 组成的, 每个 play 可以定义不同的 task 任务, 可以定义在不同的主机上执行任务, 可以定义变量...
- 一个 playbook 存在多个play, 我们又称之为 multi play ，多个 play 
- **每个play的组成是由4个部分组成的** 
	- target 部分
		- **定义这个 play 叫什么名字** 
		- **定义这个 play 中的任务会在哪些主机上执行** 
		- 定义这个 play 中配置参数是什么—>和ansible.cfg一模一样, 不过优先级比它高 
	- vars 部分
		- **定义变量的, 让下面的task任务可以引用这些变量** 
		- **可以直接在play中定义变量, 可以引用外部的变量文件...** 
	- tasks 部分 
		- **要在被控节点执行的所有的任务都是在这个 tasks 部分里面写的** 
		- **对于task任务来说, 一个task任务就是调用一个模块** 
	- handlers 部分 
		- handlers在ansible中属于触发器, 也就是说只有特定的情况下才会执行handlers 
		- handlers其实是属于特殊的tasks, 它下面可以执行多个task任务

## 2.5 handlers 部分补充
- **handlers属于特殊的tasks, 是属于play四大部分之一, 所以他们的层级关系是一样的** 
- **handlers是触发器, 只有特定的情况下才会去执行handlers下面的任务** 
	- 特定的情况: 监控一个task任务, 当这个task**任务的返回状态是changed的时候**, 则触发handlers任务
- 无论监听的这个task任务是什么时候执行的, handlers下面的任务只会在所有的任务完成最后去执行 
- 测试
	- ```bash
		- name: play3
	  hosts: all
	  tasks:
	  - name: task1
	    shell: ls /etc/passwd
	    notify: aaaa
	
	  - name: task2
	    shell: ls /etc/group
	
	  handlers:
	  - name: aaaa
	    shell: echo handlers
	    
	    这种方式监听了某个task任务, 即使在handlers下面编写了很多很多的任务, 但是最后执行handlers任务的时候, 只会执行最后一个handlers任务
	  ```
- **如果要想执行handlers下面多个task任务, 你需要加入一个关键字 listen** 
	- ```bash
		- name: play3
		  hosts: all
		  tasks:
		  - name: task1
		    shell: ls /etc/passwd
		    notify: aaaa
		
		  - name: task2
		    shell: ls /etc/group
		
		  handlers:
		    - name: handlers1
		      listen: aaaa
		      shell: echo handlers
		
		    - name: handlers2
		      listen: aaaa
		      shell: echo aaaa
	  ```
- **如果执行任务中, 有任何一个任务报错, 即使监听的任务是changed状态, handlers任务也不会触发** 
- **如果需要强制执行handlers任务, 加上force_handlers** 
	- ```bash
		- name: play3
		  hosts: all
		  force_handlers: yes
		  tasks:
		  - name: task1
		    shell: ls /etc/passwd
		    notify: aaaa
		
		  - name: task2
		    shell: lss /etc/group
		
		  handlers:
		    - name: aaaa
		      shell: echo handlers
	  ```
- 什么时候使用 handlers
	- 在部署web服务的场景下, 我们可以使用notify监听安装某个软件包的任务, 然后最后把启动这个服务的任务写到handlers中
