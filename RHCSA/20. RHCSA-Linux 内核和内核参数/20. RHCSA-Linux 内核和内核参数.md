# 1. 内核概述
- 内核的帮助文档, 需要安装 **`kernel-doc`** 软件包 
- Linux 内核是操作系统核心部分 
- 内核的功能
	- 系统初始化: 检测硬件资源并启动系统
	- 进程调度: 决定进程什么时候运行以及运行多久
	- 内存管理: 给运行的进程分配内存
	- 安全: 支持权限, selinux和防火墙规则
	- 提供buffers和cache加速硬件访问
	- 支持标准网络协议和文件系统
- Linux 中支持多个内核同时存在的
	- ```bash
		[root@rhel9 boot]# ls 
		vmlinuz-0-rescue-77f9b0944429487bb930e1cee1231718
		vmlinuz-5.14.0-362.8.1.el9_3.x86_64
	  ```
- 什么是内核模块?
	- 内核模块可以理解为是驱动程序, 为了让内核识别硬件或者操作系统, 驱动就是以内核模块的形式存在的
- **内核的组成** 
	- **内核文件** 
	- **initramfs文件** 
	- **内核模块** 

# 2. 内核模块
- 内核模块是内核的功能. 内核本身功能较少, 但是可以通过插入内核模块来为内核提供对应的功能
- **内核是一个模块化, 可以通过插入各种内核模块为内核提供对应的功能** 
- 内核模块在操作系统上**以文件的形式**存在的, 内核要加载内核模块的时候其实加载的就是这个文件
	- ```bash
		# 模块的工作目录是 /usr/lib/modules 
		[root@mubai632 ~]# ll /usr/lib/modules  # 显示系统中存在的内核
		drwxr-xr-x. 3 root root   19  1月 31 02:09 5.14.0-360.el9.x86_64
		drwxr-xr-x. 7 root root 4096  1月 31 02:15 5.14.0-362.8.1.el9_3.x86_64
		
		# 通过 uname -r 显示当前使用的是哪个内核
		[root@mubai632 ~]# uname -r
		5.14.0-362.8.1.el9_3.x86_64
		
		# 查看内核目录
		[root@mubai632 ~]# ls /usr/lib/modules/5.14.0-362.8.1.el9_3.x86_64/
		build          modules.alias.bin          modules.builtin.bin      modules.devname      modules.order        source      updates
		config         modules.block              modules.builtin.modinfo  modules.drm          modules.softdep      symvers.gz  vdso
		kernel         modules.builtin            modules.dep              modules.modesetting  modules.symbols      System.map  vmlinuz
		modules.alias  modules.builtin.alias.bin  modules.dep.bin          modules.networking   modules.symbols.bin  systemtap   weak-updates
		
		# 查看内核文件
		[root@mubai632 ~]# ls /usr/lib/modules/5.14.0-362.8.1.el9_3.x86_64/kernel/
		arch  block  crypto  drivers  fs  kernel  lib  mm  net  samples  sound  virt
		#每一个目录中都是内核模块的文件
		#内核模块文件的后缀是.ko或者.ko.xz
	  ```
- 查看系统加载的内核模块
	- ```bash
		# 查看系统加载了哪些内核模块
		命令 : lsmod
		[root@mubai632 ~]# lsmod
		Module                  Size  Used by
		snd_seq_dummy          16384  0
		snd_hrtimer            16384  1
		nft_fib_inet           16384  1
		nft_fib_ipv4           16384  1 nft_fib_inet
	  ```
- 加载和卸载内核模块, 以及依赖模块依赖关系文件
	- ```bash
		命令 : modprobe 模块名  # 加载内核模块
		命令 : modprobe -r 模块名  # 卸载内核模块
		
		卸载模块的时候会提示无法卸载, 因为被其他依赖所调用, 需要卸载其依赖才能卸载成功
		依赖关系的文件位置 /usr/lib/modules/5.14.0-362.8.1.el9_3.x86_64/modules.dep
	  ```
- 查看内核模块的详细信息
	- ```bash
		命令 : modinfo 模块名
	  ```
- 案例
	- 假设Linux系统的物理网卡是intel的网卡, 但是系统无法识别这张网卡, 说明你没有安装网卡的驱动. 也就是说你没有网卡的 .ko 内核模块文件
	- 硬件的驱动程序都是硬件的产商提供的—>intel的网卡, 你去intel的官网下载网卡驱动程序
	- 下载的驱动文件最好是源码包, 因为源码包可以在各个系统上实现编译安装, 识别大部分的系统
	- 编译安装之后就会得到 .ko 或者 .ko.xz 的文件, 并且自动将依赖写入 /usr/lib/modules/5.14.0-362.8.1.el9_3.x86_64/modules.dep 文件中
	- 使用源码安装, 在最后还会更新你的initramfs文件, 将你安装的模块写入到 initramfs 文件中
	- 如果没写入到 initramfs 文件中, 你就必须需要在开机之后使用 `modprobe 模块名` 才能识别并加载这个模块

# 3. /proc目录
- /proc 目录: 此目录是开机的时候才会有数据的, 目录下的内容反应的是系统运行时候的状态. 在此目录下, 目录的名字是数字, 而这些数字就是 **pid** 
- /proc/cgroups 文件
	- cgroups: ctroller groups控制组
	- 作用: 限制进程使用的cpu 内存等资源
- /proc/cpuinfo 文件
	- cpuinfo: 记录操作系统的cpu信息
	- flags 表示 cpu 的指令集, 就是 cpu 支持的功能
	- **如果要支持虚拟化的化, cpu必须要有vmx/svx的指令集** 
-  /proc/partitions 文件: 记录系统的分区和磁盘信息
-  /proc/filesystems 文件: 记录系统支持的文件系统类型
-  /proc/meminfo 文件: 记录系统的内存信息
