# 1. umask
- umask 决定系统上的用户创建出来的文件的默认权限是什么
	- ```bash
		[root@mubai632 ~]# umask
		0022
		
		# 设置umask值, 临时生效
		[root@mubai632 ~]# umask 555
		[root@mubai632 ~]# umask
		0555
	  ```

- 用户创建的默认文件权限是系统计算出来的
	- **固定公式**
		- 普通文件: **默认权限=666-umask** 
		- 目录文件: **默认权限=777-umask** 

- 为什么普通文件的默认权限是从 **666** 开始计算的, **这是因为系统中创建的普通文件是不允许携带 x 权限的** 

- 有时可能会发生普通文件和目录文件计算出的 umask 值不同, **这是因为系统中创建的普通文件是不允许携带 x 权限的** , 如果umask的值中有能创建出普通文件存在 x 权限的**自动 +1** 
- **如果通过目录文件默认权限和普通文件默认权限计算出来的umask值不一致, 一定要以目录默认权限为主**
- 要计算umask值的话, 仅需要通过目录文件默认权限来计算umask值就可以

- 永久修改umask值
	- ```bash
		在变量配置文件中添加
		umask 对应的值
	  ```

# 2. 三大特殊权限
- Linux 系统三大基本权限 : R / W / X 
- Linux 系统三大特殊权限 : SUID / SGID / SBIT 

## 2.1 suid 特殊权限
如果有一个**二进制文件**(可以管理系统的), 想要让**普通用户**也可以执行的话, 那么这个时候可以**赋予SUID权限** 

- **对普通文件的意义** 
	- 如果一个文件具备suid权限, 则运行这个文件的时候是以文件的拥有者身份去执行的
	- suid 只针对于 **二进制文件(命令)** 有效果, 对于脚本文件没有任何意义
- 对目录文件没有任何意义

- **查看文件是否具备 suid 权限** 
	- ```bash
		[root@mubai632 ~]# ll /usr/bin/passwd
		-rwsr-xr-x. 1 root root 32648 Aug 10  2021 /usr/bin/passwd
		# 如果拥有人的 x 变成了 s , 说明这个文件具备 suid 权限
			s：说明它有x权限
			S：说明它没有x权限
		
		[root@mubai632 ~]# stat /usr/bin/passwd
		File: /usr/bin/passwd
		Size: 32648           Blocks: 64         IO Block: 4096   regular file
		Device: 10303h/66307d   Inode: 101905393   Links: 1
		Access: (4755/-rwsr-xr-x)  Uid: (    0/    root)   Gid: (    0/    root)
		# 4755 其中的4, 代表的是文件具备 suid 权限
		Access: 2026-11-14 09:25:11.504964878 +0800
		Modify: 2021-08-10 23:53:40.000000000 +0800
		Change: 2026-01-31 09:14:46.785885356 +0800
		Birth: 2026-01-31 09:14:46.785885356 +0800
	  ```

- **设置文件的suid权限** 
	- 通过chmod命令和字符方式设置
		- ```bash
			chmod u+s 文件名  # 添加文件的 suid 权限
			chmod u-s 文件名  # 删除文件的 suid 权限
		  ```

	- 通过chmod命令和数字方式设置
		- ```bash
			chmod 4xxx 文件名
				记得把文件的原有权限也带上, 这样的话原有权限不会改变
		  ```

## 2.2 sgid 特殊权限
- **对于普通文件的意义** 
	- 如果一个文件具备 sgid 权限, 则运行这个文件的时候是以文件的所属组身份去执行的
	- sgid 只针对于 **二进制文件(命令)** 有效果，对于脚本文件没有任何意义
- **对于目录文件的意义(很重要)** 
	- 目录文件具备 sgid 权限的话, 则在目录下新创建的文件都会继承这个目录文件的拥有组身份

- **查看文件是否具备 sgid 权限** 
	- ```bash
		[root@mubai632 ~]# ll /usr/bin/touch 
		-rwxr-sr-x. 1 root root 94048 Jan 6 2023 /usr/bin/touch 
		#拥有组的 x 变成了 s , 说明具备sgid权限
			s：说明它有x权限
			S：说明它没有x权限
			
		[root@mubai632 ~]# stat /usr/bin/touch 
		File: /usr/bin/touch 
		Size: 94048 Blocks: 184 IO Block: 4096 regular file 
		Device: 10303h/66307d Inode: 101683975 Links: 1 
		Access: (2755/-rwxr-sr-x) Uid: ( 0/ root) Gid: ( 0/ root) 
		# 2755 其中的2, 代表的是文件具备 sgid 权限
		Access: 2026-03-15 11:12:21.360861983 +0800 
		Modify: 2023-01-06 19:50:11.000000000 +0800 
		Change: 2026-03-15 11:12:12.546802655 +0800 
		Birth: 2026-01-17 17:09:18.537822169 +0800
	  ```

- **设置文件的suid权限** 
	- 通过chmod命令和字符方式设置
		- ```bash
			chmod g+s 文件名  # 添加文件的 sgid 权限
			chmod g-s 文件名  # 删除文件的 sgid 权限
		  ```

	- 通过chmod命令和字符方式设置
		- ```bash
			chmod 2755 文件名
				记得把文件的原有权限也带上, 这样的话原有权限不会改变
		  ```

## 2.3 sbit 特殊权限 (sticky bit)
**sbit权限目的是为了防止大家都在一个共享目录中, 别人把你的文件删除掉**

- 对于普通文件没有任何意义
- **对于目录文件的意义** 
	- 目录文件具备 sbit 权限的话, 则这个目录下的文件**只有文件的拥有人**才可以对其进行**删除和重命名** 

- **查看文件是否具备sbit权限** 
	- ```bash
		[root@mubai632 ~]# ll -d /tmp/
		rwxrwxrwt. 21 root root 4096 Mar 15 11:17 /tmp/ 
		# 其他人的 x 变成了 t , 说明文件具备sbit权限 
			t: 说明它有x权限 
			T: 说明没有x权限
			
		[root@mubai632 ~]# stat /tmp/ 
		File: /tmp/ 
		Size: 4096 Blocks: 8 IO Block: 4096 directory 
		Device: 10303h/66307d Inode: 33554561 Links: 21 
		Access: (1777/drwxrwxrwt) Uid: ( 0/ root) Gid: ( 0/ root) 
		# 1777 其中的2, 代表的是文件具备 sbit 权限 
		Access: 2026-03-15 08:50:39.847141672 +0800 
		Modify: 2026-03-15 11:17:58.959130233 +0800 
		Change: 2026-03-15 11:17:58.959130233 +0800 
		Birth: 2026-01-17 17:08:39.624476062 +0800
	  ```

- **设置文件的sbit权限** 
	- 通过chmod命令和字符方式设置
		- ```bash
			chmod o+t /tmp  # 添加文件的 sbit 权限
			chmod o-t /tmp  # 删除文件的 sbit 权限
		  ```

	- 通过chmod命令和数字方式设置
		- ```bash
			chmod 1777 /tmp 
				记得把文件的原有权限也带上, 这样的话原有权限不会改变
		  ```

# 3. ACL 权限
ACL(访问控制列表) : 其实管理的还是基本权限, 只不过ACL权限可以更加精细化的赋予文件权限
- 例题: 
	- ```bash
		# 要求只有zhangsan用户对于/opt目录有读写的权限
		chmod o+rw /opt -->这种方式权限就太大了, 因为zhangsan用户可以读写, 其他的用户也可以读写
		
		# 不允许你修改文件的拥有人或者拥有组
		chown zhangsan:zhangsan /opt -->修改文件的拥有人/拥有组
		
		# 不允许zhangsan加入任何的组中
		usermod -aG --->将zhangsan用户加入到文件的拥有组中
	  ```

- ACL权限本质上就是: 指定 哪个用户 / 哪个用户组 对于哪个文件有哪个权限(rwx)
	- 让用户对于文件有对应的权限
	- 让用户对于文件有对应的权限

- 指定zhangsan用户对于/opt/test/目录有r和w权限—>使用ACL权限来控制
	- ```bash
		[root@mubai632 test]# setfacl -m u:zhangshan:rwx kkk/ 
		[root@mubai632 test]# ll -d kkk
		drwxrwxr-x+ 2 root root 6 Mar 16 20:06 kkk 
		
		# 当通过ll命令查看文件的时候, 如果文件权限的后面有一个+ , 说明文件具备ACL权限
	  ```

## 3.1 查看文件的 ACL 权限
- 简单的查看, 查看文件是否具备ACL权限
	- ```bash
		[root@mubai632 test]# ll -d kkk
		drwxrwxr-x+ 2 root root 6 Mar 16 20:06 kkk
		
		# 当通过ll命令查看文件的时候, 如果文件权限的后面有一个+ , 说明文件具备ACL权限
	  ```

- 详细的查看, 查看文件对应的到底是属于用户的还是用户组的ACL权限
	- ```bash
		[root@mubai632 test]# getfacl kkk
		# file: kkk         -->文件名称
		# owner: root       -->文件拥有人
		# group: root       -->文件拥有组
		user::rwx           -->文件拥有人的权限
		user:zhangshan:rw-  -->用户ACL权限, zhangsan用户对于文件会匹配到rwx权限
		group::r-x          -->文件拥有组的权限
		group:user:rwx      -->用户组ACL权限, user组对于文件会匹配到rwx权限
		mask::rwx           --------->ACL权限掩码, 决定有效的ACL权限是什么
		other::r-x          -->其他人的权限
	  ```

## 3.2 查看文件 ACL 权限注意的时候
如果文件赋予了ACL权限, 那么通过ls命令或者stat命令看到的文件的拥有组的权限 **实际上看的是ACL的mask值, 而且如果通过chmod修改文件的拥有组权限, 实际上修改的是mask值** 
实验: 
- ```bash
		# 查看没有赋予ACL权限之前的目录权限
		[root@mubai632 test]# ll -d kkk
		drwxr-xr-x 2 root root 6 Mar 16 20:06 kkk
		[root@mubai632 test]# stat kkk
		File: kkk
		Size: 6               Blocks: 0          IO Block: 4096   directory
		Device: 10303h/66307d   Inode: 1255693     Links: 2
		Access: (0755/drwxr-xr-x)  Uid: (    0/    root)   Gid: (    0/    root)
		[root@mubai632 test]# getfacl kkk
		# file: kkk
		# owner: root
		# group: root
		user::rwx
		user:zhangshan:rw-
		group::r-x
		mask::rwx
		other::r-x
		
		
		# 查看没有赋予ACL权限之前的目录权, 并查看权限
		[root@mubai632 test]# setfacl -m u:zhangshan:rw kkk
		[root@mubai632 test]# ll -d kkk
		drwxrwxr-x+ 2 root root 6 Mar 16 20:06 kkk
		[root@mubai632 test]# stat kkk
		File: kkk
		Size: 6               Blocks: 0          IO Block: 4096   directory
		Device: 10303h/66307d   Inode: 1255693     Links: 2
		Access: (0775/drwxrwxr-x)  Uid: (    0/    root)   Gid: (    0/    root)
		[root@mubai632 test]# getfacl kkk
		# file: kkk
		# owner: root
		# group: root
		user::rwx
		user:zhangshan:rw-
		group::r-x
		mask::rwx
		other::r-x
		
		
		# 当设置了acl后, 使用chmod修改文件的拥有组权限
		[root@mubai632 test]# chmod g-x kkk
		[root@mubai632 test]# getfacl kkk
		# file: kkk
		# owner: root
		# group: root
		user::rwx
		user:zhangshan:rw-
		group::r-x                      #effective:r--
		mask::rw-     # 值改变
		other::r-x
  ```
- 如果想要查看目录的原有的拥有组权限, 通过getfacl命令查看

## 3.3 修改文件的 ACL 权限
- 修改文件的用户ACL权限, 如果用户不存在则会报错
	- ```bash
		setfacl -m u:用户名:权限 文件名
	  ```

- 修改文件的用户组ACL权限, 如果组不存在则会报错
	- ```bash
		setfacl -m g:用户组名:权限 文件名
	  ```

- 删除文件的ACL权限
	- ```bash
		setfacl -b 文件 : 删除文件的所有ACL权限
		setfacl -x u:用户名 文件名 : 删除文件的用户ACL权限
		setfacl -x g:用户组名 文件名 : 删除文件的用户组ACL权限
	  ```

## 3.4 权限的优先级
- **只要文件具备ACL权限, 那么一定会优先匹配ACL权限** 
- **权限的匹配顺序** 
	1. 匹配用户的ACL权限, 未匹配上, 匹配第2条 
	2. 匹配用户的基本权限(**是否为文件的拥有者**), 未匹配上, 匹配第3条 
	3. 匹配用户组的ACL权限, 未匹配上, 匹配第4条
	4. 匹配用户组的基本权限(**是否在文件的所属组**), 未匹配上, 匹配第5条
	5. 只能匹配其他人的权限

## 3.5 ACL 默认权限 (ACL继承)
- ACL继承: 对目录赋予一个默认的ACL权限, 在目录下创建的所有的新的文件及其子文件都会继承这个目录的ACL权限
	- **-d 选项 : 创建默认 ACL 权限** 
		- ```bash
			# 第一种方式, 让子目录继承ACL默认权限
			[root@mubai632 test]# setfacl -d -m u:zhangshan:rwx kkk
			[root@mubai632 test]# getfacl  kkk
			# file: kkk
			# owner: root
			# group: root
			user::rwx
			group::r-x
			other::r-x
			default:user::rwx
			default:user:zhangshan:rwx
			default:group::r-x
			default:mask::rwx
			default:other::r-x
			
			# 第二种方式, 让子目录继承ACL默认权限
			[root@mubai632 test]# setfacl -m d:u:zhangshan:rwx kkk
			[root@mubai632 test]# getfacl  kkk
			# file: kkk
			# owner: root
			# group: root
			user::rwx
			group::r-x
			other::r-x
			default:user::rwx
			default:user:zhangshan:rwx
			default:group::r-x
			default:mask::rwx
			default:other::r-x
			
			
			# 但父文件没有ACL权限, 你还需要赋予一个ACL权限
			[root@mubai632 test]# setfacl -m u:zhangshan:rwx kkk
			[root@mubai632 test]# getfacl kkk
			# file: kkk
			# owner: root
			# group: root
			user::rwx
			user:zhangshan:rwx
			group::r-x
			mask::rwx
			other::r-x
			default:user::rwx
			default:user:zhangshan:rwx
			default:group::r-x
			default:mask::rwx
			default:other::r-x
			
			# 正常顺序是先将父目录文件赋予ACL权限, 再给予子文件及其子文件ACL权限
			# 目录赋予了默认ACL权限之后, 对目录本身是没有影响的, 只有目录下新的文件才会继承, 此时如果想要访问目录的话, 最好也给一个ACL权限
		  ```
	- **-k 选项 : 删除默认 ACL 权限** 
		- ```bash
			 [root@rhel9 opt]# setfacl -k kkk
			 # 如果在在有ACL默认权限的时候创建一个子目录文件, 使用这条命令之后, 仅会删除掉指定的目录的默认权限, 其子目录的默认权限不会被删除掉
		  ```

## 3.6 修改 ACL 权限文件的基本权限
- 当文件赋予了ACL权限之后, ls命令看到的拥有组的权限变成了mask值. 此时通过chmod g的方式去修改, 修改的其实是mask值
	- ```bash
		对于文件来说, 如果要修改的是拥有人和拥有组的权限, 直接通过chmod可以修改
		如果要修改拥有组权限：setfacl -m g::权限 文件
	  ```

## 3.7 修改 ACL 权限文件的 mack 值
- ```bash
	setfacl -m m::权限 文件名
  ```

# 4. sudo 
- sudo: 是Linux系统的一个提权的工具. 可以让**用户提权到另外一个用户的身份来执行命令** (就是使用另一个用户的身份)
- 普通用户没有权限执行useradd创建用户, 这个时候可以为其配置sudo提权, 让这个普通用户提权到root身份来执行useradd命令

- **如果想要用户执行sudo提权, 那么一定要修改配置文件, 赋予它sudo提权的操作** 
	- 给用户配置sudo的话, 只有这个用户才能使用sudo提权
	- 给用户组配置sudo的话, 这个组中的所有用户都可以使用sudo提权
	- 可以配置 sudo 的位置
		- **配置文件/etc/sudoers** 在这文件中配置
		- **配置目录/etc/sudoers.d** 在这个目录下配置, 只要格式正确, 文件名是什么都行
	- 配置格式
		- ```bash
			root    ALL=(ALL)       ALL  # 为用户配置
			%wheel  ALL=(ALL)       ALL  # 为用户组配置
			# ALL 表示所有
			
			# 格式
			允许哪个用户使用sudo提权 在哪个主机上可以提权=(可以提权到那个用户) 提权后可以执行的命令1,命令2,...
			zhangsan mubai632=(root) /usr/sbin/useradd
			#多用户, 多主机名, 多个提权后的用户, 多个命令之间全部使用逗号隔开
		  ```

- sudo 常用选项
	- ```bash
		sudo -u 用户名 : 提权到指定用户执行命令
		sudo -V : 显示版本信息和变量 
		sudo -k : 强制要求下一次执行sudo验证用户密码, 默认5m内不需要验证
		sudo -l : 列出当前用户的的sudo配置
		sudo -i : 提权并登录到root用户
	  ```

- NOPASSWD 表示不需要验证用户密码
	- ```bash
		root    ALL=(ALL)       NOPASSWD:ALL
	  ```

## 4.1 sudo 的别名
- 配置sudo的时候, 可能一句话写的很长, 不那么直观
- 可以使用sudo别命来更直观的表示
	- ```bash
		在配置文件中有, 但是并不全, 使用man手册
		man -k sudo # 查看sudo的手册目录
		man sudoers
		Alias ::= 
				'User_Alias'  # 指定用户
				'Runas_Alias' # 指定提权后的用户
			    'Host_Alias'  # 指定主机名
			    'Cmnd_Alias' 或 'Cmd_Alias'  # 指定使用命令
		
		# 格式, 别名一定要大写
		User_Alias SUDO_USERS=zhangsan,demo,lisi,wangwu,memeda01
		Host_Alias SUDO_HOSTS=ALL
		Runas_Alias SUDO_SUDOUSERS=root,admin
		Cmnd_Alias SUDO_CMDS=/usr/sbin/useradd
		SUDO_USERS SUDO_HOSTS=(SUDO_SUDOUSERS) NOPASSWD:SUDO_CMDS
	  ```
