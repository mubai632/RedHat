# 进程概述
- 什么,是进程?
	- 进程: 系统上应用程序运行的一个实例,而进程占据的是内存的空间
- 进程的分类:
	- 父进程: 负责派发任务给子进程
	- 子进程: 负责执行父进程派发的任务

系统中, 每一个进程都会被分配一个ID号, 这个就是进程ID, process id → PID
系统中, 有一个PID为 **1** 的进程, 此进程是系统所有进程的父进程，所有进程都是由这个PID为 **1** 的进程派发出来的, PID为 **1** 的进程就是systemd

**提要: 只有父进程才能结束子进程**
- **特殊的两个进程** : 
	- **孤儿进程** : 子进程的父进程意外退出, 导致子进程变成孤儿进程(人为导致)
		- 父进程意外退出, 子进程变成孤儿进程, 会被 **systemd** 接管, 接管后 **systemd** 就是孤儿进程的父进程, 然后就会结束掉这个孤儿进程
	- **僵尸进程** : 子进程完成任务后, 会发送信号给父进程, 父进程就会结束掉子进程, 但父进程未收到信号, 就不会结束掉子进程, 子进程会一直占用系统资源, 这样就会成为僵尸进程
		- 用户干预, 强制结束掉僵尸进程

**进程会继承用户的访问权限, 子进程会继承父进程的访问权限**
**pstree 命令 : 查看进程数**

# 查看进程
## ps 命令
- 常用ps命令
	- **ps -axu : 如果要查看进程消耗的资源**
	- **ps -ef : 如果要查看进程的PPID**
	- ps -axo : 按照用户指定的格式进行输出, 可以加 `--sort=参数` 比如 `%cpu` , 以cpu进行排序, 默认升序, `-%cpu` 降序
- ps 命令: 查看静态的进程
	- ```bash
		[mubai@mubai632 ~]$ ps
	    PID TTY          TIME CMD
		1887 pts/0    00:00:00 bash
		1957 pts/0    00:00:00 ps
		
		PID : 进程ID
		TTY : 终端设备, 表示此进程是运行在哪个终端上的
			pts/0 : 第1个伪终端; pts/1 : 第2个伪终端......(ssh,图形化标签页)
			tty : 终端设备
			? 代表内核的进程, 不在任何终端上
		TIME : 进程获得CPU时间分片是多少, 值越大获得CPU资源越多, 反之越少
		CMD : 运行进程的命令
	  ```
- **-a选项** : 查看所有终端的进程
	- ```bash
		[mubai@mubai632 ~]$ ps -a
	    PID TTY          TIME CMD
		1344 tty1     00:00:00 dbus-run-sessio
		1345 tty1     00:00:00 dbus-daemon
		1346 tty1     00:00:00 gnome-session-b
		1354 tty1     00:00:01 gnome-shell
		2001 pts/0    00:00:00 ps
	  ```
- **-x选项** : 查看不属于任何终端的进程
	- ```bash
		[mubai@mubai632 ~]$ ps -x | head
		PID TTY      STAT   TIME COMMAND
		1854 ?        Ss     0:00 /usr/lib/systemd/systemd --user
		1855 ?        S      0:00 (sd-pam)
		1878 ?        S      0:00 sshd: mubai@pts/0
		1887 pts/0    Ss     0:00 -bash
		1913 ?        S      0:00 sshd: mubai@notty
		1926 ?        Ss     0:00 /usr/libexec/openssh/sftp-server
		2005 pts/0    R+     0:00 ps -x
		2006 pts/0    S+     0:00 head
	  ```
- **-u选项** : 选项查看进程的PID, 消耗的CPU资源, 消耗的内存资源, 占据虚拟内存空间, 实际占用的真实物理内存空间
	- ```bash
		[mubai@mubai632 ~]$ ps -u
		USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
		mubai       1887  0.0  0.3 224096  5588 pts/0    Ss   20:51   0:00 -bash
		mubai       2024  0.0  0.1 225480  3524 pts/0    R+   21:22   0:00 ps -u
		
		VSZ : 虚拟内存
		RSS : 真实内存
		对于系统的程序来说, 它运行的时候是会向操作系统申请内存资源的---》对标的就是VSZ(单位是KB)
	  ```
- **-e选项** : 查看所有进程
- **-f选项** : 显示更多的格式
- ```bash
	[mubai@mubai632 ~]$ ps -ef | head -n 5
	UID          PID    PPID  C STIME TTY          TIME CMD
	root           1       0  0 20:50 ?        00:00:00 /usr/lib/systemd/systemd rhgb --switched-root --system --deserialize 31
	root           2       0  0 20:50 ?        00:00:00 [kthreadd]
	root           3       2  0 20:50 ?        00:00:00 [rcu_gp]
	root           4       2  0 20:50 ?        00:00:00 [rcu_par_gp]
  ```
- **-o选项** : 按照用户指定的格式进行输出
	- ps -axo 输出格式
	- 输出格式：ps L, 可以显示出有哪些格式
	- ```bash
		[mubai@mubai632 ~]$ ps -axo user,pid,ppid,%cpu,%mem,vsz,rss,cmd | head -n 5
		USER         PID    PPID %CPU %MEM    VSZ   RSS CMD
		root           1       0  0.0  0.7 104196 13432 /usr/lib/systemd/systemd rhgb --switched-root --system --deserialize 31
		root           2       0  0.0  0.0      0     0 [kthreadd]
		root           3       2  0.0  0.0      0     0 [rcu_gp]
		root           4       2  0.0  0.0      0     0 [rcu_par_gp]
	  ```

## top 命令
- top 命令: 查看动态的进程
	- 进入到top命令的交互界面, **默认3s刷新一次**
	- top -d 1 : 1s刷新一次
	![](top命令交互界面.png)
	- ```bash
		top - 21:55:43 up  1:05,  1 user,  load average: 0.00, 0.00, 0.00
		Tasks: 269 total,   1 running, 268 sleeping,   0 stopped,   0 zombie
		%Cpu(s):  0.0 us,  3.1 sy,  0.0 ni, 96.9 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
		MiB Mem :   1732.1 total,    655.6 free,    820.2 used,    423.0 buff/cache
		MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.    911.9 avail Mem
		
		load average: 0.00, 0.00, 0.00 CPU的平均负载(1分钟/5分钟/15分钟)
		us: user用户态(用户空间)消耗CPU的资源-->用户打开的所有的应用程序属于用户空间的
		sy: system内核态(内核空间)消耗CPU的资源-->内核自己打开的进程, 以及内核自动调整优先级的进程, 而且linux系统上有一些命令就是属于内核态的
		ni: 进程的nice值->理解为进程的优先级, 计算进程的优先级的时候也会消耗CPU资源, 修改过nice值的进程消耗的CPU资源
		id: 空闲率 CPU的空闲率
		wa: wait CPU的等待时间-->等待的是磁盘IO时间-->说明磁盘性能远远跟不上CPU处理性能-->检查以下是不是磁盘故障了或者磁盘读写性能太差
		hi: 硬中断, 等待硬中断的时间, 如果值很大的话, 说明硬件经常发送中断信号-->数据包从网卡进出
		si: 软中断.
		st: 被hypervisor偷取的时间, 只有当你的系统是虚拟机才需要关注, 物理服务器不需要关注, 如果值特别大, 说明当前虚拟机得到的物理CPU资源不多
		buff/cache都是属于内存中的数据, 你可以称之为缓存, 缓存的出现是为了加速读写性能的
		buff缓冲区: 占据的是内存的空间, 解决的是写性能的, 加速写性能
			CPU处理后的数据不是直接写入到磁盘中, 而是写入到内存中的缓冲区中, 当缓冲区保存的数据达到了一定的大小, 缓冲区中的数据会落盘到磁盘中
		cache缓存: 占据的是内存的空间, 解决的是读性能的, 加速读性能
			第一次从磁盘文件中读取图片, 第一次读肯定会慢, 读出来的时候, 同时会把图片缓存到内存中的cache里面, 下一次如果还是读取的同一个图片, 这个时候cpu就不会从硬盘中读取了而是读取内存的数据
	  ```

## 其他进程工具
- pgrep : 根据进程名字的关键字和条件过滤进程(**通过程序的名字来查询进程的工具**)
	- 常用选项: 
		- ```bash
			pgrep -U : 查找某个用户的进程id
			pgrep -G : 查找某个组的进程id
			pgrep -P : 根据父进程ID, 查找出所有子进程id
			pgrep -l : 不仅打印pid, 也打印进程名
			pgrep -o : 表示如果该程序有多个进程正在运行, 则仅查找最老的, 即最先启动的(多个进程时即父进程PID)
			pgrep -n : 表示如果该程序有多个进程正在运行, 则仅查找最新的, 即最后启动的
			pgrep -d : 定义多个进程之间的分隔符,, 如果不定义则使用换行符
		  ```

- pidof : 根据进程名过滤进程
	- pidof和pgrep之间区别在于: pgrep只需要过滤出进程名字的关键字即可, pidof必须要写上进程名字全程
	- 脚本中常用
## 进程的优先级
- 当系统资源紧张, 进程优先级高的, 会优先获得系统资源
- nice值: 表示优先级, 范围是 `-20 -- 19` , 值越小越优先
- 系统共有2个优先级; 
	- PR ：动态优先级, 属于内核自动调整的
	- NI ：nice值, 属于用户人工调整的, 可以理解为静态优先级
		- ```bash
			#运行进程的时候指定nice值
			nice -n 数字 命令
			
			#调整已经存在的进程的nice值
			renice -n 数字 pid
		  ```

# 进程之间的通信
- 进程和进程之间的通信方式 : 
	- 管道
	- 信号signal：在linux系统中，信号是最为常见的进程通信方式
		![](消息队列.png)
	- 共享内存
	- socket 套接字 : 只有本机才能够进行访问, 即使别的主机获取到了登录账号密码, 也无法实现登录, 所以更加安全
		![](套接字.png)
	- 消息队列
- kill 工具 : 用来发送信号的工具
	- 对进程的操作可以通过发送不同的信号来实现, 直接给进程发送信号, 不需要用户界面
	- 通过名称或者数字来确定一个信号: 
		- **Signal 15** : 正常退出进程(默认)
		- **Signal 9** : 强制退出进程(致命)能不使用就不要使用
		- **Signal 1** : 重新加载配置, 不需重启服务, 直接读到最新的配置, 好处在于**进程的ID是不会发生变化**的
	- ```bash
		kill 信号 进程
	  ```
- 通过进程名称发送信号 : `killall [信号] 进程名称` 一般是用来批量结束进程的
- 根据命令名称, 特定用户等模式发送信号 : `pkill 选项 <pattern>` 可以结束掉一个用户,一个终端的所有进程

# 后台作业
所谓后台作业(进程): 就是将前端的进程放到后台持续执行
例子: ping 命令
	前台作业的特点在于: 用户无法在终端执行命令
	将作业放到后台运行, 不会影响用户的其他操作
```bash
	[mubai@mubai632 ~]$ ping qq.com &
	[1] 2899
	
	# [1] : 代表作业号
	# 2899 : 进程号
```
```bash
	查看当前终端的后台作业
	[mubai@mubai632 ~]$ jobs
	
	将后台作业放在前端运行
	[mubai@mubai632 ~]$ fg %作业号
	
	将前台作业放到后台运行
	[mubai@mubai632 ~]$ bg %作业号
	
	将前台作业放到后台停止
	ctrl z
	
	结束作业
	kill 进程号 / kill %作业号
```
**作业会随着终端的退出而退出**
- 但有一种方式是可以让作业不随着终端的退出而退出
	- nohup命令, nobup配合&使用
		- ```bash
			[mubai@mubai632 ~]$ nohup ping qq.com &
		  ```
